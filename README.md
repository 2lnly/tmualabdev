# TMUA Lab

A free, offline-capable practice site for the **Test of Mathematics for University
Admission** — the admissions test used by Imperial, LSE, Warwick, Durham and
others. Modelled on [esatlab.co.uk](https://esatlab.co.uk), rebuilt for the TMUA.

Everything is static: no build step, no framework, no backend, no accounts. All
progress lives in the visitor's own `localStorage` and never leaves the browser.

---

## Running it

```bash
# any static server will do
python3 -m http.server 8787
# then open http://localhost:8787
```

Opening `index.html` straight off disk works too — the scripts are plain
`<script src>` tags, not ES modules, precisely so `file://` does not break.

## Deploying it

Upload the folder. That is the whole deployment story — GitHub Pages, Netlify,
Cloudflare Pages, Vercel, S3, or a directory on any web server. There is nothing
to configure and nothing to run.

## The past-paper bank

UAT-UK publishes the TMUA papers from 2016 to 2023 with worked answers and
answer keys, as free preparation material. All sixteen are transcribed into the
bank, and **every answer is re-checked against the official key at build time** —
`tools/build-past.js` refuses to emit a bank where any answer disagrees.

```
data/past/answer-keys.json   the 16 official keys, parsed from the key PDFs
data/past/YYYY-PN.json       one transcribed paper (the editable source)
data/past/TRANSCRIPTION-GUIDE.md   the contract a transcription must meet
assets/js/bank-past.js       GENERATED by tools/build-past.js — never edit
```

```bash
node tools/build-past.js          # rebuild the bank, checking every answer
node tools/check-paper.js 2019-P1 # validate one paper (read-only)
```

Questions carry `src: {year, paper, number}`, which drives the provenance chip
in the UI, the **Real past papers** filter in the question bank, and the
**Sit a real past paper** mode on the mock page — that one serves a paper's
twenty questions in their original order under the real 75-minute countdown.

The PDFs themselves are not in this repo. To re-fetch and re-render them, the
pipeline is: pull the PDFs from UAT-UK's S3 bucket, parse the key PDFs (two
different layouts — 2016/2017 interleave the two papers column-wise, later years
list them sequentially), then rasterise each question page with PyMuPDF at 170
dpi, cropped to content. The 2016 and 2017 PDFs have broken font encodings, so
their text layer is unusable and transcription must work from the images.

## Adding questions

Append to `assets/js/bank-p1.js` or `bank-p2.js`:

```js
q({ id: 'P1-ALG-13', t: 'alg', sp: 'Quadratics · discriminant', d: 3,
  q: 'For which $k$ does $x^2 + kx + 9 = 0$ have equal roots?',
  o: ['$k = \\pm 6$', '$k = 6$', '$k = \\pm 3$', '$k = 9$', 'no such $k$'],
  a: 0,
  e: 'Equal roots need $k^2 - 36 = 0$, so $k = \\pm 6$.' });
```

| Field | Meaning |
| --- | --- |
| `id` | Unique. Convention: `P{paper}-{TOPIC}-{nn}` |
| `t` | Topic key — see `TL.TOPICS` in `core.js` |
| `sp` | Specification point, shown as a chip |
| `d` | Seed difficulty 1–5; drives the calibrated facility and target time |
| `q` | Stem. Prose is HTML; maths goes between `$…$` |
| `o` | 4-8 options. The real paper varies: Paper 1 usually 6-7, Paper 2 often 8 |
| `a` | Zero-based index of the correct option |
| `e` | Worked answer, same `$…$` convention |

Maths is written in a LaTeX subset: `\frac`, `\sqrt`, `^`, `_`, `\left…\right`,
`\binom`, `\text`, `\mathbb`, Greek letters, and the usual relation, logic and
set symbols. Anything unrecognised falls back to upright text rather than
breaking the page.

**Check new questions before shipping them:**

```bash
node tools/check.js
```

It validates structure, LaTeX balance, duplicate options, prose accidentally
left inside `$…$`, and per-paper topic coverage. It cannot tell you the marked
answer is right — do that yourself, and make sure no distractor is also
defensible.

## How scoring works

1. Each question carries a calibrated facility — the proportion of candidates
   expected to answer it correctly, derived from its difficulty.
2. A set's expected mark is the sum of those facilities, which is how kind or
   cruel that particular draw was.
3. Your mark is shifted in log-odds by the difference between that and an
   average paper, giving the proportion you would have scored on a typical one.
4. That proportion is mapped onto the TMUA 1.0–9.0 scale and then onto an
   approximate percentile of the published distribution.

Sets under 10 questions get no score at all; sets of 10–19 are pulled towards
the middle of the scale and labelled as indications rather than predictions.
Every result page shows the working.

The review queue implements the same rule the site documents: a wrong answer
makes a question due immediately, and leaving the queue takes two correct
answers **in review**, at least 36 hours apart. Any miss resets it.

## Things you will want to change

Search for `EDIT ME` in the source. There are three:

- `index.html` — the "who runs this" card (name, course, avatar initial) and the
  paragraphs beneath it.
- `community.html` — the Discord, review and support links, currently `#`.
- The footer disclaimer in `assets/js/shell.js`, if your affiliations differ.

Also worth reviewing before launch: the university list in `guide.html`, which
is accurate at the time of writing but changes every admissions cycle.
